# FXTools Configurations

The FXTools natively load default configurations from the `statejson`, which is the `fx.state.json` file that is creates automatically. Changing the values in these affect how the commands that used them behave. This saves the user from manually typing out entire commands everytime.

The JSON file is generated automatically whenever anything configuration wise is required. By default, the values are:-

```py
DEFAULT_SCHEME = {
    "DEFAULT_ARCH": "x86_64",
    "THREADS": 4,
    "RUNTIME_CORES": 4,
    "QEMU_FULLSCREEN": True,

    "USER_NAME": None,
    "USER_EMAIL": None,
    "USER_SIGN_FILES": None
}
```

## Default Architecture

Defines the default architecture that FXTools assume for any function. Currently, the only valid value is `x86_64`, but support for more are planned.

## Threads

Number of threads used by the program when compiling or any intensive task. This helps speed up the process, but note that you must use a sufficiently right number, as, at some point, it reaches a saturation point.

## Runtime Cores

When emulating the kernel, this value decides the number of cores that the emulated CPU runs with.

## QEMU Fullscreen

A boolean on whether the QEMU emulation launches in fullscreen by default or not.

## User Name

Fetched by the `fx config setup-profile` command to read from `git config --global user.name` to get the user's name. If one is not found, it is asked.

## User Email

Similar to user name, it is fetched by the `fx config setup-profile` command, using `git config --global user.email` to get the email. If one is not found, it is asked.

## User Sign Files

Path to the folder where the private and public key of the user is stored, generated by the `fx sign setup` command, which, by default, stores everything into a `.farix` folder in the user directory. It is not stored inside the repository for safety. Were it stored in the project repository, exposing the private key ruins the point. If it is put inside `.gitignore`, there exists the chance of accidently losing them. Keeping them aside, since they need not be made everytime, ensures safe keeping.
